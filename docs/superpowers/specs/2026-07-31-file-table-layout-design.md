# WxCleaner 文件表格与滚动交互设计

## 背景

当前 `FileTable` 使用 `pack(side="left")` 分别排列表头和数据行。路径列通过 `expand=True` 占据剩余空间，但表头与每行没有共享列轨，因此窗口尺寸变化或长路径出现时，右侧列可能发生视觉漂移。

用户希望参考 PureMac 的清理列表体验：表头与行严格对齐，路径列弹性伸缩，表格内容独立滚动，底部状态与删除操作保持固定，同时保留当前 WxCleaner 的选择、右键菜单和 macOS 触控板行为。

## 目标

1. 让表头和所有数据行使用完全一致的列定义与列宽策略。
2. 让“文件路径”列占据剩余空间，其他列不被长路径挤压。
3. 让表头固定、表格正文垂直滚动、底部进度和操作区固定。
4. 保留现有行选择、Cmd/Shift 多选、悬停、右键菜单、状态颜色和删除流程。
5. 保留现有 macOS 原生 `MouseWheel` delta 处理，并兼容 Tk 8.6 与支持 `<TouchpadScroll>` 的 Tk 版本。

## 非目标

- 不替换为 `ttk.Treeview`。
- 不增加横向滚动条。
- 不改变扫描、重复文件判定、删除安全策略或业务数据结构。
- 不修改 `/Applications/PureMac.app`，也不依赖其二进制实现。

## 方案

继续使用当前 `Canvas + CTkFrame` 的表格实现。将表头和每个数据行内部的列布局统一改为 `grid`，通过同一组列配置建立空间关系：

| 列 | 策略 | 默认宽度 |
| --- | --- | ---: |
| 序号 | 固定宽度，居中 | 60 px |
| 文件路径 | `weight=1`，占据剩余空间，左对齐 | 最小 180 px |
| 大小 | 固定宽度，居中 | 110 px |
| 修改时间 | 固定宽度，居中 | 170 px |
| 状态 | 固定宽度，居中 | 80 px |

表头和行使用相同的列索引、`minsize`、`weight` 和内边距。每个行 frame 维持固定高度，`grid_propagate(False)` 保证行高度不会被文本请求尺寸改变。路径标签使用单元格宽度显示，文本超出时直接裁剪，不改变右侧固定列的位置。

表头继续位于滚动 Canvas 之外，正文 frame 作为 Canvas window 只在垂直方向滚动。Canvas resize 时只更新正文 frame 的 viewport 宽度；正文 frame 的列轨由网格管理器重新分配路径列剩余宽度。原生窄滚动条继续位于正文右侧。

## 交互与滚动

- 鼠标滚轮和 macOS 触控板事件仍由 Canvas、正文 frame、行 frame 及其标签统一委托到现有滚动处理器。
- macOS `<MouseWheel>` 保留原始 delta 幅度，并继续使用当前 `yscrollincrement`，保证小幅触控板移动不会被压成固定三行。
- 支持 `<TouchpadScroll>` 的 Tk 版本使用现有有符号 delta 解码；Tk 8.6 不支持该事件时继续跳过对应集成测试。
- 表头不随正文滚动；滚动范围只由正文内容决定。
- 空表格和内容不足以滚动时不改变现有显示行为。

## 验收标准

### 布局

- 表头和任意数据行的五个列单元格左边界、右边界一致。
- 窗口扩大或缩小时，只有路径列宽度变化，大小、修改时间和状态列保持固定宽度。
- 长路径不会遮挡或挤压大小、修改时间、状态列。
- 表头、正文和底部进度/操作区在垂直滚动时保持各自约定位置。

### 交互

- 点击任意单元格仍能选中对应行。
- Cmd 点击、Shift 范围选择、悬停、右键菜单和状态着色不回归。
- macOS 不同 delta 幅度产生不同的滚动距离。
- 当前 Tk 8.6 测试环境下，鼠标滚轮测试通过，Tk 9 专属事件测试按能力跳过。

### 验证

- 运行完整 pytest 套件。
- 启动实际 GUI，在默认窗口和缩小窗口下截图检查列对齐、长路径裁剪、正文滚动和底部固定区域。
- 不重新构建发布包，除非实现影响打包入口或用户明确要求发布。

## 变更范围

- `source/wx_gui.py`：FileTable 的表头、行布局和必要的尺寸辅助逻辑。
- `tests/test_gui_table.py`：增加列轨一致性、弹性路径列和布局行为回归测试；保留现有滚动及选择测试。
- 本设计文档：记录已确认的交互和验收约束。
